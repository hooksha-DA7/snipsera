## 1.0.8-preview.1: editor and capture refinements

Release candidate verified on 2026-11-21. Store Submission 7 is a draft with automatic publication selected; it has not been submitted for certification. This build remains a preview until Microsoft approves the matching update. The official 1.0.7 release and its downloads remain unchanged.

The editor now supports direct object selection and resize handles, inline text, seven text styles, symbol stamps and combined PNG/JPEG image layers. Named Background, Layers and Image size panels replace the combined settings control. Backgrounds include 15 gradients, solid fills, padding, alignment, aspect ratio, rounded corners, shadow and reversible trimming of uniform outer margins. The original image stays anchored and Crop applies to that image only.

Scrolling preview work adds off-UI-thread processing and interactive inspection with Fit and Follow latest controls. History gains a direct Edit action and appearance-aware surfaces. The temporary-hide restore handle is smaller while retaining click and hover restoration.

New editable saves use project version 4, readable by this candidate but not by 1.0.7 or earlier. Original pixels and embedded added images are retained. Automatic History edits use the new format too; keep copies of older projects if they must remain editable in an older app.

## 1.0.7 release: layered screenshots and preview controls

Microsoft approval and Store availability were confirmed on 19 November 2026 for Submission 6 (1152921505702444831), package 1.0.7.0. The matching GitHub build is promoted to official/Latest as Snipsera 1.0.7, preserving its immutable v1.0.7-preview.2 tag, source, filenames, bytes and hashes. Store approval does not sign the GitHub installer or complete pending native acceptance.

The exact [hosted build](https://github.com/hooksha-DA7/snipsera/actions/runs/44444517015) passed **507 automated/offscreen checks** (446 C# checks across 23 modes and 61 Python checks), with **zero compiler warnings/errors**. Package/source parity, safe ZIP paths and CRCs, manifests, Store identity/resource/block-map checks and EXE installation, synthetic launch, reinstall, increasing-version fixture upgrade, owned startup cleanup and uninstall passed on Windows Server 2025. Downloaded artifact bytes were independently verified. The isolated local app launched and its accessibility tree was readable, but black desktop screenshots prevented live deck appearance, layering and hit-target acceptance.

New screenshots join a layered deck at the bottom left instead of replacing the previous preview. The front screenshot retains its 200 × 150 card and on-image controls. Up to two narrower cards peek out behind it, with 20-DIP steps and 8-DIP side insets. Clicking an exposed edge brings that capture forward; Alt+2/Alt+3 does the same when a screenshot card has keyboard focus. Rear cards have no active sharing, drag or close controls. **+N** opens additional pending screenshots. Short displays use fewer layers, and an unpinned recording stays separate below the deck while taking one slot. Pin/Unpin keeps the same window. Ordinary overflow captures load from History on demand, while failed history saves retain recovery pixels.

The tray and overflow list offer **Clear unpinned previews** and **Reopen last dismissed capture**. Clear preserves pins and History; Reopen uses the latest saved edits and defaults to **Ctrl+Alt+Shift+6**, configurable in Settings. Existing shortcut choices survive migration. **Settings > General > Previews > Dismiss after sharing** is saved and on by default. Successful Copy, explicit Save or an accepted copy drag dismisses an unpinned screenshot. Canceled/failed actions, automatic PNG saving, pins and recording cards do not dismiss it. A missing history entry/file keeps the preview available.

Editor sharing saves edits to History first. Closing an editor does not restore an already shared state or an explicitly cleared preview; later edits can return a new preview after sharing. Late transfer completion targets its original pending capture, even in overflow, and cannot dismiss a reopened replacement. Clear and reopen also handle recovered captures that gain a new History identity on their first successful save. The pending and dismissed lists last for the current session; the preference and latest-100 History persist.

The preceding stack implementation passed **457 automated/offscreen checks** (414 C# and 43 Python) on 19 November 2026. After the layered-deck refinement, the Release build again passed with **zero warnings/errors**, and **304 focused checks passed** (261 C# and 43 Python). These cover deck geometry across DPI/monitor bounds, rear-card action restrictions, promotion, pinning, history and editor recovery, hide/restore, recordings, existing card controls, scrolling and storage workflows. The 29 new deck checks include detached light/dark renders at 100%, 150% and 200% scale; both shareable composites were visually reviewed. Overflow thumbnails own small independent pixels and their visual tree is released on close. Those earlier builds used the pinned SDK and existing dependency cache after a restore attempt was blocked by access to the user's NuGet configuration; the fresh candidate restore above has since passed.

Desktop clipboard/paste, file-picker cancellation, cross-application drops, popup/deck focus, native layering and hit targets, monitor placement and capture exclusion remain pending native acceptance. Detached renders do not establish those behaviors. Local installation and clean Windows 11 acceptance also remain pending. A separate Library window and cloud features remain future proposals. See [preview workflow](docs/PREVIEW-WORKFLOW.md).

The first hosted 1.0.7 build stopped because the pinned upstream GIF-converter archive returned HTTP 404. Build 1.0.7-preview.2 adds a hash-verified fallback to the unchanged encoder files in the prior official release. The fallback validates the entire archive and all 11 component hashes before writing runtime files; integrity failures do not switch sources. All 61 Python checks passed, including 18 dependency-retrieval regressions. The earlier source tag remains unchanged. The shipped source is `8cbb4c5fab2db5cb9d47be9fcc90cbf3ec206e11`, tag `v1.0.7-preview.2`. The submitted MSIX SHA256 is `577274a9225f499ca2fe2cdf1fb89eb4c44a8f87b32d711c9afc59e4a22961cf`. ## Update and startup release: 1.0.5

Known notices and acknowledgement persist across restarts. GitHub actions open the owned release page; installers are never downloaded or executed automatically. ## Recording update: 1.0.3

GitHub preview: **1.0.3**, 4 November 2026. The current official Store/GitHub release is **1.0.2**.

Recording setup now uses two compact floating panels with source icons, editable pixel dimensions, capture toggles and separate Record GIF / Record Video actions. Quality, FPS, resolution and notification settings are available under the sliders icon. The bar shows GIF conversion progress and keeps its two-click Discard available while Stop is pending.

Area selection uses physical pointer coordinates through mouse release, validates a frame inside one display, and passes an explicit monitor-local crop and output canvas to the recorder. Canceling selection returns a distinct result so a Record action cannot fall back to an old source.

Compact/Balanced GIFs sample the palette and use faster ordered dithering; High retains full palette analysis and error diffusion. Output FPS, dimensions and timing remain as chosen. Six-second synthetic 720p/1080p benchmarks were about three times faster in Balanced mode; results depend on content and hardware.
